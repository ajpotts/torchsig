Title: Investigate PyTorch NVML initialization warning

Summary

Importing PyTorch and querying CUDA device availability in the TorchSIG
development environment emits the following warning:

    UserWarning: Can't initialize NVML

The warning originates from `torch/cuda/__init__.py` while PyTorch attempts to
determine the CUDA device count through NVML.

Observed behavior

- PyTorch version: `2.13.0+cu130`.
- `torch.cuda.is_available()` returns `False`.
- `torch.cuda.device_count()` returns `0`.
- `nvidia-smi` reports that it cannot communicate with the NVIDIA driver.

Impact

GPU-backed TorchSIG workflows are unavailable in the affected environment, and
CUDA capability checks produce a warning. CPU-only workflows may continue to
operate, but the warning can add noise to test and development output.

Proposed investigation

- Confirm that the host has an NVIDIA GPU and that GPU access is intended for
  this development environment.
- Verify that the NVIDIA driver is installed, loaded, and compatible with the
  CUDA-enabled PyTorch build.
- If running in a container or virtualized environment, verify that NVIDIA
  devices and driver libraries are exposed to it.
- If the environment is intentionally CPU-only, use a CPU-only PyTorch build or
  document and narrowly suppress the expected capability-check warning.

Acceptance criteria

- In a GPU-enabled environment, `nvidia-smi` succeeds and PyTorch CUDA device
  queries complete without an NVML warning.
- `torch.cuda.is_available()` and `torch.cuda.device_count()` reflect the GPUs
  made available to the environment.
- In an intentionally CPU-only environment, the expected configuration is
  documented and routine TorchSIG commands do not emit an unexpected NVML
  warning.
