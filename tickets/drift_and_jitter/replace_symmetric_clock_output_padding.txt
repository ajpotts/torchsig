Title: Replace symmetric zero padding for short clock-impairment output

Summary

When the sampling-clock engine produces fewer samples than the input,
`_preserve_sampling_clock_output` pads zeros on both ends. This shifts retained
content and can introduce hard discontinuities unrelated to the modeled clock
effect. It also obscures which input-time interval the returned samples
represent.

Proposed change

Define the temporal alignment contract for output shorter than the requested
length. Prefer selecting sampling positions that cover the intended input
record. If padding is unavoidable, place it according to group-delay-aware
alignment and expose or document the boundary policy.

Acceptance criteria

- Large positive drift returns the requested output length without an
  unexplained content shift.
- Padding placement follows the same group-delay and initial-phase convention
  as normal output cropping.
- Tests cover zero, one, and multiple missing output samples.
- Tests verify complex64 dtype and finite output.
- Boundary discontinuities and their expected effect are documented if zero
  padding remains part of the policy.
