Summary
Update YOLOLabel so the class identifier used in generated YOLO annotations can be selected from signal metadata rather than always using the canonical class index.
Motivation
GroupingLabel can add alternative labels such as family_name and family_index to signal metadata. However, YOLOLabel currently uses the signal's canonical class index when generating:
[class_index, x_center, y_center, width, height]
This means consumers that want family-level or other grouped YOLO labels must rewrite the class ID after YOLO labels have already been generated.
That requires independently retrieving class names and YOLO boxes and matching them afterward, which is unnecessarily fragile.
Proposed Change
Allow YOLOLabel to specify which metadata field supplies the YOLO class ID.
For example:
GroupingLabel("family"), YOLOLabel(class_index_field="family_index"),
The resulting YOLO label would then be:
[family_index, x_center, y_center, width, height]
The default should remain the existing canonical class index so this change is backward compatible.
The API should be generic rather than family-specific so arbitrary GroupingLabel configurations can be used.
Acceptance Criteria


        
      YOLOLabel supports selecting the metadata field used for the YOLO class ID.

        
      Existing behavior remains the default.

        
      Works with metadata generated by GroupingLabel.

        
      Supports custom groupings, not only the built-in family grouping.

        
      Produces the same bounding-box coordinates regardless of the selected class-index field.

        
      Includes tests for canonical class labels, family labels, and a custom grouping.

        
      Provides a clear error when the requested metadata field is unavailable.
