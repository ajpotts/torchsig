## Summary

Preserve the configured class name when a named signal generator expands into
a `ConcatSignalGenerator`.

Previously, `TorchSigIterableDataset.init_signal_generator()` resolved a string
name before recursively adding the concat generator's children. The configured
name was discarded during that recursion. Children without an intrinsic
`class_name` were consequently unlabeled, causing class-based per-signal
configuration and sampling groups to fail during dataset initialization.

## Changes

- Add an optional `class_name` argument to `init_signal_generator()`.
- Capture the configured string name before resolving the signal generator.
- Propagate that name through recursive concat expansion.
- Pass the preserved name to `add_signal_generator()` for each child.
- Add a regression test using a mocked named concat with two unlabeled child
  generators.

The regression test verifies that both children receive the logical configured
class name and that the family's aggregate sampling probability is divided
equally between them.
