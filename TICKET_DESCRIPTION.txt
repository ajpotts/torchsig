Title: Use the calculated sampling-position increment

Problem

`sampling_clock_impairments` calculates and validates
`nominal_position_increment`, but the resampling loop advances by the
unadjusted `drate`. Initial output storage is also sized with `drate`, so the
calculated drift adjustment has no effect on the nominal sampling path.

Scope

- Advance NumPy and Numba nominal positions with that fixed increment.
- Size initial output storage using the effective increment.
- Preserve the existing accumulated Gaussian drift and jitter behavior.

Acceptance criteria

- Positive drift produces fewer raw output samples than zero drift.
- Negative drift produces more raw output samples than zero drift.
- Drift-only processing preserves its existing RNG behavior.
- NumPy and Numba use the same nominal-position increment.

Out of scope

Changes to the drift or jitter model and public transform documentation.
