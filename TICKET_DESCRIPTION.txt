Title: Finalize the sampling-clock API, physical units, and documentation

Problem

The corrected resampler and drift models need a clear public contract. Linear
drift should support physical PPM-per-second units without long-record position
accumulation error. Zero-magnitude transforms should be identity-preserving by
default, and callers need an explicit policy when drift exhausts available
input samples. Users and reviewers also need concise documentation of model
semantics and bandwidth limitations.

Scope

- Default ClockDrift and ClockJitter to zero initial sampling phase.
- Add initial_phase to the public jitter APIs.
- Add initial_drift_ppm, drift_rate_ppm_per_second, and sample_rate.
- Evaluate linear-drift positions with closed-form integration.
- Add edge, zeros, wrap, and raise boundary policies.
- Default boundary handling to edge extension.
- Document the models, units, alignment, boundary behavior, merge stack, and
  near-Nyquist prototype-filter limitation.
- Update the clock drift and jitter examples.
- Retain the supporting analysis and reference material.

Acceptance criteria

- Zero magnitude and zero phase preserve aligned passband input by default.
- Physical linear drift follows d[k] = d0 + r*k/fs.
- Linear positions match analytical closed-form results.
- Missing or invalid sample-rate units are rejected.
- Every boundary policy has deterministic tested behavior.
- Public class and functional APIs expose consistent parameters.
- Documentation identifies the stack targets and filter validity limitation.
- Focused sampling-clock and transform tests pass.

Dependency

This ticket depends on 165-clock-drift-models, which follows the three-branch
engine foundation ending at 165-clock-initial-phase.
