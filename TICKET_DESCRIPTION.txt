Title: Add initial sampling phase and signed ClockDrift controls

Problem

The corrected clock engine does not expose receiver initial sampling phase
through every API layer. ClockDrift also needs an explicit signed offset range
and a selectable linear or logarithmic parameter distribution.

Scope

- Add initial_phase to the NumPy and Numba engine APIs.
- Add initial_phase to functional clock_drift and ClockDrift.
- Validate phase in the half-open interval [0, 1).
- Use a signed default drift_ppm range.
- Add linear and log10 drift-range sampling.
- Reject logarithmic sampling for signed or nonpositive ranges.
- Add public API, validation, and NumPy/Numba parity tests.

Acceptance criteria

- Nonzero phase changes output consistently in both engines.
- Zero phase retains the prior engine alignment.
- Invalid phase bounds are rejected.
- Signed drift ranges use linear sampling.
- Positive drift ranges may use logarithmic sampling.
- Public transforms preserve length and complex dtype.

Dependency

Depends on 165-clock-engine-hardening.
