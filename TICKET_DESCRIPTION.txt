Title: Harden sampling-clock output capacity

Problem

Sampling-clock output is written into a preallocated buffer. Future signed
rate-offset behavior can produce more samples than the initial estimate, which
would otherwise result in an uncontrolled out-of-bounds write.

Scope

- Check capacity before NumPy and Numba output writes.
- Grow output and random-value buffers geometrically when needed.
- Apply a defensive maximum growth multiplier.
- Raise a clear error if the defensive limit is exhausted.

Acceptance criteria

- Existing in-capacity output remains numerically unchanged.
- The compiled kernel rejects undersized output storage before writing.
- Wrapper-managed growth preserves existing random values.
- Exhausting the defensive limit raises a clear `RuntimeError`.

Out of scope

Changes to drift, jitter, validation, or public API semantics.
