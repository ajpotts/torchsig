Title: Align seeded NumPy and Numba sampling-clock streams

Problem

The NumPy implementation draws one jitter value at a time while the Numba
wrapper retains an interleaved compatibility pool. The two implementations
should consume one equivalent seeded jitter stream and produce numerically
equivalent results.

Scope

- Generate one float64 jitter value per output sample.
- Pass that stream directly to the compiled kernel.
- Preserve generated values when capacity grows.
- Test combined drift and jitter with identical seeds.

Acceptance criteria

- Identical seeds produce reproducible output in each implementation.
- NumPy and Numba outputs agree for combined drift and jitter.
- The compiled kernel accepts one jitter value per output sample.
- Output remains complex64.

Out of scope

Clock-model semantics and public transform documentation.
