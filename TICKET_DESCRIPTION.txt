Title: Add time-varying sampling-clock drift models

Problem

The existing ClockDrift behavior represents a constant sampling-rate offset,
not physical drift. A useful augmentation model needs rate error that changes
over the capture while remaining deterministic under a supplied random seed.
It should cover a deterministic ramp and representative stochastic clock-noise
processes without changing the corrected resampler established by MR 1.

Scope

- Replace constant-offset semantics with time-varying drift.
- Add linear, random-walk, and filtered-noise rate-error trajectories.
- Treat drift_ppm as the signed endpoint for linear drift and its absolute
  value as the RMS scale for stochastic models.
- Support an explicit initial sampling phase and initial rate error.
- Integrate drift into absolute sampling positions.
- Maintain equivalent NumPy and Numba execution.
- Add analytical, reproducibility, validation, and parity tests.

Acceptance criteria

- Linear drift follows its specified initial-to-final PPM ramp.
- Random-walk and filtered-noise trajectories are seed-reproducible.
- Independent jitter does not accumulate into later nominal positions.
- Drift does accumulate into sampling position.
- Invalid models and nonpositive position increments are rejected.
- NumPy and Numba results agree for all three models.
- Public transforms preserve output length and complex dtype.

Dependency

This ticket depends on the corrected sampling-clock engine and phase API
delivered through 165-clock-initial-phase.

Out of scope

Physical PPM-per-second units, selectable boundary behavior, notebooks, and
extended user documentation are handled by MR 3.
