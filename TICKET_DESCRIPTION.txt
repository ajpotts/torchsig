Title: Define drift as a fixed sampling-rate offset

Problem

Clock drift is currently generated as accumulated Gaussian noise. The
`drift_ppm` parameter should instead represent one signed sampling-rate offset
that remains constant for the duration of the signal.

Scope

- Convert `drift_ppm` to a signed nominal-position increment.
- Advance NumPy and Numba nominal positions with that fixed increment.
- Size initial output storage using the effective increment.
- Stop consuming random values for drift-only calls.

Acceptance criteria

- Positive drift produces fewer raw output samples than zero drift.
- Negative drift produces more raw output samples than zero drift.
- Drift-only processing does not consume random values.
- NumPy and Numba implement the same signed-offset behavior.

Out of scope

Independent jitter semantics and public transform documentation.
