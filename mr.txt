Optimize TorchSig’s Doppler implementation by preserving complex64 processing, caching reusable polyphase filters, handling near-unity rates efficiently, and adding an optional batched API for signals sharing a Doppler rate. Fix length, dtype, validation, and filter-cache issues, and add focused unit and optional performance benchmarks.
Expected outcomes include roughly 40–50% faster common scalar Doppler calls and substantial additional gains for batched processing, while preserving numerical and spectral behavior.

Summary
This MR improves the correctness and performance of TorchSig’s wideband Doppler resampling.
Changes
Fix Doppler output-length handling for long signals.
Validate invalid physical parameters and multidimensional scalar inputs.
Preserve complex64 throughout resampling by using dtype-aware float32 filters.
Cache base and finalized interpolation/decimation filters.
Bypass filtering when the effective resampling rate is unity.
Improve fractional-rate selection near unity.
Avoid unnecessary final dtype copies.
Add doppler_batch for equal-length signals sharing one velocity.
Extend polyphase resampling to operate along the final array axis.
Add optional scalar, batched, and dataset-generation benchmarks.
Add unit tests for shape, dtype, numerical precision, spectral performance, caching, edge cases, and reproducibility.
Repair the outdated passband-ripple fallback benchmark.
Performance
Compared with the original implementation:
Short and medium scalar Doppler calls are approximately 40–50% faster.
Long scalar calls are approximately 12–16% faster.
Dataset generation with Doppler is approximately 50–65% faster.
Batched processing is approximately 69–94% faster for short and medium signals and 11–28% faster for long signals.
Numerical comparisons remain within complex64 precision, with filter passband and stopband behavior preserved.
