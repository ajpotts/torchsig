## Summary

Extract sampling-clock position generation from polyphase interpolation and add configurable jitter models.

## Changes

- Add a reusable `SamplingPositions` dataclass containing:
  - retained nominal output indices
  - nominal positions
  - actual impaired positions
  - polyphase upsampling rate
  - input-sample position and timing-error accessors
- Add `generate_sampling_positions()` with support for:
  - independent Gaussian absolute timing jitter
  - accumulated Gaussian sampling-period jitter
  - stationary AR(1) absolute timing jitter
- Preserve and document the existing drift interpretation:
  - `drift_ppm` adjusts the nominal sampling period
  - a Gaussian period-error random walk is integrated into absolute timing error
- Apply the existing padded-input position bounds and output-capacity limit.
- Preserve nominal output alignment when impaired positions are skipped.
- Refactor `sampling_clock_impairments()` to pass generated positions to `polyphase_resample_at_positions()`.
- Update the Numba wrapper to use the shared clock model and a position-only Numba interpolation kernel.
- Keep `sampling_clock_impairments()` returning only the impaired IQ array.

## Behavioral note

The default jitter model is now independent absolute timing jitter. Jitter values are interpreted in input-sample periods and converted to polyphase units before interpolation.

## Testing

Added coverage for:

- independent jitter mean, variance, and lag-one correlation
- period-jitter increment variance and correlation
- AR(1) stationary variance and lag-one correlation
- zero jitter and drift
- fixed-seed reproducibility
- invalid-position filtering and nominal-index alignment
- jitter-model validation
- output-capacity limits
- Python/Numba parity for every jitter model

Focused result: `108 passed, 4 skipped`.

## Performance

An on-MR/off-MR benchmark comparison initially identified a regression caused by generating each sampling position in a Python loop. The common independent-jitter and drift paths were subsequently vectorized with NumPy.

Targeted benchmark means after the optimization:

| Benchmark | Off-MR baseline | Initial MR implementation | Optimized MR implementation |
| --- | ---: | ---: | ---: |
| Clock jitter | 252.1 µs | 715.9 µs | 234.8 µs |
| Clock drift | 259.1 µs | 1,097.8 µs | 237.2 µs |

The optimized implementation is approximately 7% faster for clock jitter and 8% faster for clock drift than the off-MR baseline in these runs. The targeted benchmark rerun completed with `2 passed`.
