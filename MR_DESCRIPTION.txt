Title: Define drift as a fixed sampling-rate offset

Target branch: 3.0.0-dev

Summary

This MR fixes the unused `nominal_position_increment` in both sampling-clock
implementations. `drift_ppm` now applies a signed, fixed sampling-rate offset
instead of accumulated random drift.

Changes

- Advance nominal positions using the validated drift-adjusted increment.
- Size initial output storage for positive and negative rate offsets.
- Remove random-number consumption from drift-only processing.
- Test positive, zero, and negative drift in NumPy and Numba.

Verification

`pytest -q tests/utils/test_sampling_clock_fixed_drift.py tests/utils/test_sampling_clock_validation.py tests/utils/test_dsp_numba.py`
