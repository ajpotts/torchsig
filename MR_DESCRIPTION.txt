Title: Finalize the sampling-clock API and documentation

Target branch: 165-clock-drift-models
Ultimate target: 3.0.0-dev

Summary

This MR completes the sampling-clock work with physical linear-drift units,
closed-form position evaluation, identity-preserving defaults, selectable
boundary behavior, examples, and user documentation. It is the final MR in the
three-branch stack.

Changes

- Add initial_drift_ppm, drift_rate_ppm_per_second, and sample_rate.
- Use exact closed-form integration for capture-normalized and physical linear
  drift instead of cumulative floating-point position updates.
- Default initial phase to zero for ClockDrift and ClockJitter.
- Expose initial_phase through the jitter functional and class APIs.
- Add boundary_mode values edge, zeros, wrap, and raise; default to edge.
- Add analytical position, boundary-policy, validation, response, and public
  API tests.
- Document model semantics, equations, boundaries, alignment, and the
  near-Nyquist prototype-filter limitation.
- Update clock drift and jitter notebooks.
- Include supporting methodology, analysis, proposal, and reference material.

Compatibility notes

- ClockDrift now models time-varying drift rather than a constant offset.
- Initial phase defaults to zero instead of being randomized.
- Exhausted output defaults to edge extension instead of zero padding.
- Set boundary_mode="zeros" to request the previous padding behavior.

Review guidance

Review this branch against 165-clock-drift-models. Comparing it directly with
3.0.0-dev will include the two preceding MRs. The analytical tests provide
small exact examples for closed-form positions and boundary behavior.
