Title: Add equal-probability sampling by configured label group

Summary

This follow-on MR allows TorchSigIterableDataset to balance signal generation
using an existing GroupingLabel configuration.

Previously, GroupingLabel could assign grouped output labels, but generator
selection remained uniform per signal class. Groups containing many classes
therefore appeared more frequently than groups containing only a few classes.

TorchSigIterableDataset now accepts sampling_grouping. Groups may define an
explicit probability or a relative likelihood, and the resulting group share
is distributed uniformly among the generators within that group. If no
weights are configured, represented groups remain equiprobable.

Usage

The same GroupingLabel instance can control both generator selection and
output labeling:

    grouping = GroupingLabel("grouping.yaml")

    dataset = TorchSigIterableDataset(
        signal_generators=["bpsk", "qpsk", "8psk", "2fsk"],
        transforms=[grouping],
        target_labels=[grouping.index_label],
        sampling_grouping=grouping,
        metadata=metadata,
    )

TorchSigIterableDataset also accepts a grouping YAML path or equivalent
configuration mapping directly through sampling_grouping.

Built-in family preset

TorchSIG's canonical class-to-family mapping is available as the built-in
"family" preset. Users do not need to recreate or maintain a family YAML file:

    dataset = TorchSigIterableDataset(
        signal_generators="all",
        sampling_grouping="family",
        metadata=metadata,
    )

To use the same family definitions as output labels:

    family_grouping = GroupingLabel("family")
    dataset = TorchSigIterableDataset(
        signal_generators="all",
        sampling_grouping=family_grouping,
        transforms=[family_grouping],
        target_labels=[family_grouping.index_label],
        metadata=metadata,
    )

The preset is generated from CLASS_FAMILY_DICT. Family names are sorted to
provide stable numeric indices, and each GroupingLabel receives an independent
configuration copy.

Probability and likelihood configuration

Weights are added directly to group entries. Explicit probabilities must sum
to 1.0:

    groups:
      - name: phase
        regex: 'psk$'
        probability: 0.25
      - name: frequency
        regex: 'fsk$'
        probability: 0.75

When any group uses probability mode, a group without a probability emits a
warning and receives probability 0.0. A positive probability assigned to a
group with no available generator is rejected because that distribution
cannot be realized.

Likelihoods are relative weights and are normalized over represented groups:

    groups:
      - name: phase
        regex: 'psk$'
        likelihood: 1
      - name: frequency
        regex: 'fsk$'
        likelihood: 3

A missing likelihood defaults to 1.0. Probability and likelihood cannot be
mixed in one grouping configuration.

Equal-probability calculation

Generator probability is calculated as:

    1 / (number of represented groups * generators in the selected group)

For example, if bpsk, qpsk, and 8psk belong to one group and 2fsk belongs to
another:

    bpsk: 1/6
    qpsk: 1/6
    8psk: 1/6
    2fsk: 1/2

The three PSK generators collectively receive 50% probability, and the FSK
generator receives the other 50%.

Only groups represented by the dataset's configured signal generators
participate in the distribution. A configured group with no available
generator cannot produce samples and therefore receives no probability.

When a generated component is rejected because it overlaps an existing
component, TorchSIG retries within the originally selected group. This avoids
biasing accepted output components toward groups whose signals are easier to
place.

Pre-generation metadata requirement

Sampling groups must use metadata available on each generator before signal
generation. Class-name groupings, including exact, regex, formula, and default
rules, can be balanced this way.

Values produced or measured during generation cannot determine which
generator is selected. For example, the realized signal bandwidth is not
available at generator-selection time. TorchSIG raises a descriptive
ValueError when the grouping source is unavailable before generation instead
of silently using an unbalanced distribution.

Public API

- Added the sampling_grouping argument to TorchSigIterableDataset.
- Added balance_signal_generators_by_group() for applying or reapplying a
  grouping after all generators have been configured.
- Added GroupingLabel.match() so grouping rules can classify a source value
  without constructing or mutating a Signal.
- Added the built-in GroupingLabel("family") preset and
  GroupingLabel.available_presets().

Example update

The string-grouping classifier example now passes the same GroupingLabel to
sampling_grouping and to the dataset transform chain. Its
WorkerSeedingDataLoader therefore receives labels and generated samples based
on the same YAML grouping.

Testing

The new tests verify:

- Exact generator probabilities for groups with unequal class counts.
- Empirical group frequencies over repeated generator selections.
- Constructor configuration from a YAML grouping path.
- A clear error when the grouping source is unavailable before generation.
- GroupingLabel.match() behavior without a Signal object.
- Equal group frequencies among accepted generated components.
- Preservation of the selected group across overlap retries.
- Errors for empty datasets and generators that match no configured group.
- Correct and independently copied canonical family presets.
- Equal sampling through sampling_grouping="family".
- Exact group probabilities and normalized group likelihoods.
- Warning and zero probability behavior for omitted probabilities.
- Validation for mixed, invalid, and unrealizable group weights.
